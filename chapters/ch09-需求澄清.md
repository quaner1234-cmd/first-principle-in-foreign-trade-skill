# 第九章 需求澄清与打样：从客户语言到可确认标准

## Core Idea
打样环节的核心是把客户的语言翻译成技术语言，再变成双方都能检查、确认、追溯的标准。翻译链：**客户语言 → 技术语言 → 可确认标准**。每断一次，客户对"你能不能理解我"的信任降一档。

## Frameworks Introduced
- **翻译链三步**：
  1. 客户语言变成技术选项（"太透了" → 克重不足？织法太松？需要里衬？局部加厚？）
  2. 让客户确认方向（给选项，不开放提问——客户只需要做选择题）
  3. 确认后的内容变成可追溯标准（进工艺单、标注来源）

- **设计确认逐条批注**：开发简报 + 客户红批注——让客户逐条确认理解，把"我以为"变成"客户确认"

## Key Concepts
- **客户语言 → 技术语言**："太透了"不是标准，"要里衬（结构/克重/覆盖区域）"才是
- **翻译链断裂的代价**：客户说"加长魔术贴"，你只加长 5cm，实际要的是调节结构整体重设计——多一轮打样、多两周、多一次失望

## Mental Models
- 别让客户做问答题，让他做选择题
- 客户在学你的术语（"lining 可能是正确的术语"）= 他信任这个对话

## Anti-patterns
- **停在"你想要什么"**：客户不知道答案，给 2-3 个方向让他选
- **把客户语言当一个完整需求**：一个词（"加长"）背后可能有整套结构调整
- **单方面"以为理解对了"**：不逐条确认，样品出来客户说不对

## Worked Example
沙恩（徒步裤）：客户反馈"米色面料相当透"→ 我们给选项（里衬/加层/局部织法/换面料）→ 客户确认"lining 可能是正确术语，功能性比轻量化更重要"→ 颜色方向（橄榄绿/深棕/khaki，排除红色）→ 模糊的"透"变成明确技术任务。
