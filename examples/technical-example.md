# Example — 技术假设（五金冲压件，非服装）

> 脱敏构造案例。行业：五金 / 冲压件。  
> 重点演示 Technical Hypothesis：AI **不直接宣布技术原因**。

## 假设 Company Context（虚构）

- 工厂做不锈钢冲压与简单焊接组件
- 可做 304 / 430；钛合金与复杂 CNC 需外协确认
- 表面处理：常见电镀可协调；特殊真空镀 Unknown

## 输入

> 供应商说：这个黑色不锈钢零件，这个颜色稳定性做不上去。客户要的是接近哑光黑、盐雾 72h 后不能明显发白。供应商只说“这个颜色不行”，没有给报告。

## 输出（Action Mode）

### 当前判断

**不要把“供应商说不行”当成最终技术事实。** 先把模糊观察转成可验证假设，再决定是换工艺、换供应商，还是跟客户谈 trade-off。

### Original Observation

供应商实际描述：该黑色外观在目标工况（盐雾 72h、哑光黑）下“颜色稳定性做不上去”；目前只有口头说法，无检测报告、无工艺参数、无失败样品照片。

### Candidate Explanation（假设，不是结论）

可能机制（需验证，可并存）：

1. **涂层体系不匹配**：当前黑色为普通喷涂/氧化，盐雾下底材腐蚀导致发白起霜  
2. **膜厚或前处理不足**：除油/钝化不到位，附着差  
3. **材料牌号限制**：若实际是 430 而非约定 304，耐蚀性更弱，黑色外观更易失败  
4. **供应商能力边界被表述成“颜色不行”**：真实原因可能是成本/交期/设备，而非物理极限

### Evidence Needed

- 失败件照片 + 盐雾前后对比
- 当前工艺路线：基材牌号、前处理、涂层类型、膜厚、固化参数
- 盐雾标准编号与判定方法（发白如何定义）
- 同配方在其他颜色/其他基材上的历史结果
- 第三方或客户指定实验室的小样测试计划

### Reality Verification

| 要验证什么 | 谁负责 |
|---|---|
| 基材与工艺参数真相 | Supplier（要书面工艺卡） |
| “发白”是否达到拒收标准 | Lab / 客户品质标准 |
| 是否存在可量产替代工艺 | Internal + 表面处理供应商 |
| 客户能否接受成本/交期 trade-off | Customer |

### 当前关键未知

1. **失败原因未被验证**——通过供应商证据 + 实验室测试解决；当前为软阻塞
2. 客户判定标准（什么叫“明显发白”）未操作化——通过客户确认解决；尚不是 Hard Blocker

### 下一步最小有效动作

1. 向供应商要：基材牌号、工艺路线、失败样、是否做过盐雾及报告  
2. 把客户需求写成可测标准：盐雾标准 + 时间 + 外观判定方法  
3. 并行询一家表面处理商：在 304 + 哑光黑目标下，72h 盐雾的可行工艺与成本区间（标注为询价假设）

### 承诺边界

**现在可以说**：已记录外观与盐雾目标；正在收集工艺与测试证据；不会仅凭口头“做不到”关闭项目。

**暂时不能承诺**：一定能做出稳定哑光黑；某一工艺一定过 72h；最终单价与交期。

---

### 纪律提醒

```text
Original observation
→ Candidate explanation
→ Evidence needed

```

AI 的价值是把模糊问题变成可验证假设，不是宣布“真正的技术原因”。
