# Mode 1 — Inquiry Analysis（询盘 / 资格澄清）

**触发**：需要分析询盘或资格澄清类材料（含 New Lead、Qualified Inquiry，以及「新客户但已有明确项目」）。

**不要**把本 Mode 理解成「只有第一封邮件」。是否重跑全套，由 `project-stage.md` 决定。

## 强制前置

1. 识别客户/项目与**项目阶段**（四档）
2. 检查 **Buyer Identity Evidence**；不足则跑 `auto-due-diligence.md`（与是否「新询盘」解耦）
3. 再进入事实/推断/判断

## 执行顺序

```
材料
→ 客户/项目识别 + 已有上下文
→ 项目阶段（New Lead / Qualified Inquiry / Active Project / Re-engagement）
→ 身份证据充分？不足→背调；充分→沿用；新风险→增量
→ Company Context
→ 合并事实 → 推断 → 未知
→ 真实性 / 匹配度 / 可行性
→ 最大阻塞 → 最小有效动作 → 现实验证 → 承诺边界
```

## 分析重点

1. **阶段是否判对**：首次联系但带 tech pack + 数量 → Qualified Inquiry，不是普通 New Lead
2. **外部身份证据**：可检索却未查 = 违规；查不到 = 未知，继续；持续项目无主体信息 = 仍要补背调
3. **表面请求 vs 原始目标**（推断须指向事实）
4. **行为证据**与投入档位（行为 > 需求完整度 > 可行性 > 主体 > 表面语言）
5. **Inquiry Fit**（先事实后推断）
6. **前序缺失**：只问一个补上下文问题，不盘问清单

## 报价时机

> **决定价格的关键变量是否已经足够明确。**

变量已知 → 可报价；未知 → 先澄清 1–3 个关键问题。不机械「首封不报价」。

## 常见处理

- New Lead 信息太少 → 专业回复、控制投入
- 模式不匹配 → 说明边界 + 替代方案
- 平台昵称无公司信息 → 标明无法有效主体背调，继续分析需求
- 整段聊天已给 → Active/Qualified，沿用事实，检查身份是否曾背调过

## 与 Mode 3

- 身份不足时在本 Mode 内背调即可
- 用户要深度尽调或 Deep 触发 → Mode 3 / Deep Check
