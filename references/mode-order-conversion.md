# Mode 11 — 大货推进 / Order Conversion

**触发**：样品、测试、报价或技术开发已经形成实质进展，项目开始具备从“继续开发”转向“商业收敛 / PO / Deposit”的条件。

**目标不是催客户下单**，而是回答：

> **当前已经积累的确定性，是否足以要求客户做下一层合理承诺？**

以及：

> **还有什么真正站在项目与大货订单之间？**

细则见 `references/clarity-engine.md`（Commercial Commitment Ladder、Order Conversion Check、Order Blocker 判定、Validation + Conversion）。

## 触发信号

以下任一信号出现时，应主动考虑进入本 Mode 或至少运行一次 Order Conversion Check：

- 客户已支付样品 / 开发费；
- 一轮或多轮样品已完成；
- 客户对整体方向给出正面或原则认可；
- 客户愿意再支付下一轮样品 / 测试；
- 客户寄出自己的参考样、材料或关键资源；
- 决策人、采购、管理层、Board 等开始参与；
- 客户开始问大货价格、交期、MOQ、数量、尺码 / 颜色；
- 项目存在明确销售季、上市、活动或 in-hand date；
- 剩余问题已经能够被清晰枚举。

## 判断顺序

1. **确认整体方向是否已原则成立。**
   - 如果产品核心方向仍被否定，继续 Mode 5 / 6。
   - 如果整体认可，只剩可定义修改，进入商业收敛检查。

2. **列出距离 Bulk Order 还差什么。**
   - 产品 / Fit；
   - 关键性能；
   - 正式价格；
   - 数量；
   - size / color breakdown；
   - 交期；
   - 商业条件；
   - 决策人批准；
   - PO / deposit 内部流程。

3. **区分 Order Blocker 与 Remaining Detail。**
   - 不要因为还有任何修改，就默认不能谈大货；
   - 也不要为了成交，把真正影响性能、价格、交期或量产风险的问题降级。

4. **确定 Next Customer Commitment。**
   当前最合理的承诺可能是：原则批准、数量、交期、breakdown、正式报价确认、PO、Deposit，而不是每次都直接问“什么时候下单”。

5. **设计并行路径。**
   如果最后一轮样品 / 验证不会推翻整体方向，应检查能否同步做：
   - 正式核价；
   - 量产交期；
   - 材料和关键辅料准备；
   - size / color breakdown；
   - PI / PO / deposit 条件准备。

6. **检查时间窗口。**
   对季节性产品、活动项目和上市项目，时间本身可能成为 Order Blocker。不要等最后一个样品完成后才第一次核对真实大货时间。

## 推进原则

- **不要催单，推进决定。**
- 每次推进都尽量让客户做一个清晰、有限、合理的决定。
- 客户已经投入越多，越可以合理要求更高一级的商业承诺。
- 商业推进不能越过关键技术、法律、安全或公司授权边界。
- 如果客户仍持续要求高投入开发，却长期不愿提供与阶段匹配的承诺，应降低投入并重新评估。

## 常见错误

错误：
> Sample looks good. When will you place the order?

更好的内部思路：
> 样品整体方向是否已经被认可？如果是，客户现在能否确认预计数量、目标到货时间和需要完成的最后修改？这些确认是否足以让我们同步准备正式报价和量产时间？

错误：
> 还有三个小细节没改，所以现在不能谈订单。

正确检查：
> 这三个细节会不会改变客户是否接受、正式价格、性能、交期或生产可行性？如果不会，并且量产前仍有 PP / Final Approval Gate，就不应自动阻止商业推进。
