# Decision Engine（统一判断内核）

所有场景都必须先运行同一个判断内核，而不是每个模式各自做一套分析。

## 流程

```
RAW INPUT
↓
1. 识别任务模式（10 种 Mode 之一，自动判断，不询问用户；复合输入选主模式，其余作次要引用）
↓
2. 读取 Company Context
   - company-context.local.md 存在 → 先读取
   - 不存在 → 未知公司能力标 Unknown；只问会改变决策的 1-3 个公司信息；不拒绝分析
↓
3. 提取 事实 / 推断 / 未知（带来源标签）
↓
4. 判断项目阶段
   A. 概念探索 / B. 供应商初筛 / C. 产品定义 / D. 样品推进 / E. 大货决策
↓
5. 寻找当前最大阻塞变量（最多 2 个）
↓
6. 检查公司能力与承诺边界
↓
7. 识别风险和机会
↓
8. 选择"下一步最小有效动作"（最多 3 项，按信息价值排序）
↓
9. 标明谁负责现实验证
↓
10. 决定现在能承诺什么 / 不能承诺什么
```

## 事实优先级

### 公司内部事实（从高到低）
1. 当前用户明确提供的信息
2. `company-context.local.md`
3. 当前项目材料
4. 书中的方法论
5. 模型自己的通用知识

**模型通用知识不得覆盖用户明确确认的公司事实。**
例：Company Context 已写明"工厂可做皮夹克外衣，防弹片不生产，由客户提供"，则不得再分析"需要内部确认工厂能不能做防弹产品"。

### 外部事实（法规/标准/税率/关税/物流/市场）
- 宿主有 Web/Search 工具 → 优先实时验证
- 没有搜索工具 → 必须写"需要外部验证"，不得凭模型记忆写成确定事实

## 阻塞变量清单

统一从以下变量中寻找（不要机械只从"订单五变量"选）：

- 需求真实性
- 方案匹配度
- 信任
- 预算/成本
- 时间窗口
- 技术能力
- 合规/制度
- 公司内部决策
- 供应链执行
- 信息不足

输出只给：**当前最大阻塞：X**（必要时第二阻塞，最多两个）。

## 最小有效动作原则

> 用最便宜的动作获得最有价值的下一个证据。

动作标准：成本低 / 信息增量大 / 能改变下一步判断。

禁止笼统建议（"继续跟进客户并了解需求"）。必须具体：
- ✅ "先确认客户是否接受由其自行提供防护面板。这个答案直接决定项目是否属于我方能力范围。"
- ✅ "暂不正式核价。先让面料供应商确认幅宽和 MOQ，这两个变量直接决定单耗与材料成本。"

## 提问限制

- 一次最多建议向客户确认 **1-3 个**真正会改变下一步决策的问题。
- 按 Information Value 排序："如果客户回答这个问题，我下一步会不会改变？"不会改变 → 暂时不要问。
- 看到 Unknown 不得一次抛出 6-10 个问题。
