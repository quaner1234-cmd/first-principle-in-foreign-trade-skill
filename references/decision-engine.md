# Decision Engine（统一判断内核）

所有场景都必须先运行同一个判断内核，而不是每个模式各自做一套分析。

## 流程

```
RAW INPUT
↓
1. 识别客户 / 项目；读取已有对话与项目上下文
   - 持续项目 → 沿用已有事实，禁止当成全新 New Lead 重跑
↓
2. 判断项目阶段（四档，自动，不问用户）
   New Lead / Qualified Inquiry / Active Project / Re-engagement
   - 细则：references/project-stage.md
   - 材料形态 + 商业动作成熟度；不确定且会改变下一步 → 只问一个前序问题
↓
3. 选择任务 Mode（10 种之一，由阶段 + 最新材料自动判断；复合输入选主 Mode）
↓
4. 检查 Buyer Identity Evidence 是否充分（与「是否新询盘」解耦）
   - 不足 → 公开背调（auto-due-diligence.md）；充分 → 不重复；新风险 → 增量核查
   - 背调只产出外部事实 / Risk Facts / 未发现证据，不贴客户标签
↓
5. 读取 Company Context
   - company-context.local.md 存在 → 读取
   - 不存在 → 未知标 Unknown；只问会改变决策的 1-3 个公司信息；不拒绝分析
↓
6. 合并证据：外部背调（或沿用）+ 公司上下文 + 项目事实
↓
7. 提取 事实 / 推断 / 未知（带来源标签）
↓
8. 评估真实性 / 匹配度 / 可行性（及需要时的产品推进粒度：概念→初筛→定义→样品→大货）
↓
9. 寻找当前最大阻塞变量（最多 2 个）
↓
10. 检查公司能力与承诺边界
↓
11. 识别风险和机会（Risk Facts 在此进入判断，不是在搜索时判决）
↓
12. 选择"下一步最小有效动作"（最多 3 项）
↓
13. 标明谁负责现实验证
↓
14. 决定现在能承诺什么 / 不能承诺什么
```

## 事实优先级

### 公司内部事实（从高到低）
1. 当前用户明确提供的信息
2. `company-context.local.md`
3. 当前项目材料 / 本对话已确认事实
4. 书中的方法论
5. 模型自己的通用知识

**模型通用知识不得覆盖用户明确确认的公司事实。**

### 外部事实（客户主体 / 法规 / 标准 / 税率 / 关税 / 物流 / 市场）
- 有 Web/Search → 优先实时验证
- 客户主体：按「身份证据是否充分」+ 阶段策略触发（见 `auto-due-diligence.md`），**不是**「仅新询盘才背调」
- 无搜索工具 → 写「需要外部验证」
- 「未找到」→「未发现公开证据」，不能写「不存在」

### 来源标签
`[客户原文]` `[外部背调]` `[对话上下文]` `[公司上下文]` `[技术包]` `[公开来源]` `[工具验证]`

## 阻塞变量清单

- 需求真实性 / 方案匹配度 / 信任 / 预算成本 / 时间窗口
- 技术能力 / 合规制度 / 公司内部决策 / 供应链执行 / 信息不足
- 主体可验证性（证据不足，不是「客户是假的」）
- **前序信息缺失**（持续沟通但缺线程时，可成为最大阻塞——动作用一个问题补上下文）

输出只给：**当前最大阻塞：X**（最多两个）。

## 最小有效动作原则

> 用最便宜的动作获得最有价值的下一个证据。

禁止笼统建议。必须具体。

前序缺失时的标准动作：

> 请把前面的聊天/邮件一起发我，或简单告诉我此前已经做到哪一步。

禁止因此展开 6–10 个身份/数量/报价历史盘问。

背调：身份不足才查；Quick 默认；Deep 仅高风险触发；Active 侧重增量。

## 提问限制

- 向**客户**一次最多 1–3 个会改变下一步的问题。
- 向**用户（业务员）**：能推断阶段就不要问「新还是老」；阶段不清且影响行动时，**只问一个**前序问题。
- 能公开背调得到的，不要改成问客户（除非来源冲突需澄清）。
