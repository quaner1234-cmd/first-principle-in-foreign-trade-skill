# Output Contract（输出契约）

默认输出必须短——业务员应在 **20-40 秒内读完主要结论**。背调块保持克制。

## 模板

```markdown
## 当前判断

一句话说明现在应该：**推进 / 先澄清 / 内部核实 / 外部验证 / 等待 / 升级 / 降低投入 / 关闭 / 补前序上下文**
并说明最核心理由。

**项目阶段**：New Lead / Qualified Inquiry / Active Project / Re-engagement
（一句依据。若前序缺失：写「持续沟通，前序信息缺失」——此时最小动作通常是向业务员要前序，而不是向客户盘问。）

## 外部背调事实

（身份证据不足时必出；Mode 3 / Deep 必出；已充分且无新风险可写「沿用已有」+ 一句摘要。）

**档位**：Quick Check / Deep Check / 沿用已有 / 增量核查
**Buyer Identity Evidence**：充分 / 不足

### 身份 / 业务 / 公开经营痕迹 / 最近活动 / Risk Facts / 未找到 / 来源
（格式见 auto-due-diligence.md）

无可检索身份时：
**当前无法完成有效主体背调：现有信息只能确认客户的需求内容，不能确认其商业主体。**
然后继续下方判断，不停止。

## 事实 / 推断 / 未知

### 事实
带来源标签：`[客户原文]` `[外部背调]` `[对话上下文]` `[公司上下文]` `[技术包]` `[公开来源]` `[工具验证]`

### 推断
每条说明依据，须能指向事实。禁止：精确成交概率；未检索可检索身份时的主体断言；在前序缺失时臆造已报价/已打样等历史。

### 未知
只列会改变决策的。提问上限：对客户 1–3；对业务员前序问题最多 1 个（当且仅当阶段不清会改变下一步）。

## 当前最大阻塞

1-2 个。

## 下一步最小有效动作

最多 3 项，具体动作。

前序缺失时的标准第 1 项：
请把前面的聊天/邮件一起发我，或简单告诉我此前已经做到哪一步。

## 现实验证

| 未知 | 谁验证 |
|---|---|
| … | Customer / Supplier / Technical Staff / Management / Public/Web / 业务员（前序材料） |

## 承诺边界

### 现在可以说
### 暂时不能承诺
```

## 客户回复（仅用户要求时追加）

- 不重复客户已说内容；问题 1–3 个；不虚构能力；未确认不承诺
- 不把背调内部结论写进客户邮件
- 语言跟随客户
