# Auto Due Diligence（证据获取层）

> **背调不是给客户打分，而是为下一步判断补充外部事实。**
>
> **搜索负责发现事实，Skill 负责区分事实与推断，人负责决定这些事实是否足以改变行动。**

## 触发逻辑（与「是否新询盘」解耦）

正确问题是：

> **当前有没有足够的客户身份事实（Buyer Identity Evidence）？**

而不是：

> 这是新询盘吗？

```text
判断项目阶段（见 project-stage.md）
↓
检查身份事实是否充分
↓
不足 → 背调（不问「要不要背调」）
充分 → 不重复背调
↓
出现新的身份/合规风险信号 → 增量核查（不必全量重做）
```

例：已聊两周的 Active Project，但业务员从未查过公司、Skill 首次接手 → 仍应发现「Buyer Identity Evidence：不足」并补做背调，而不是因「不是新询盘」跳过。

Mode 3（尽调）可单独触发 Deep Check；与阶段默认策略不冲突。

## Buyer Identity Evidence：何为「充分」

**充分**（可不重复全量背调）≈ 已有可引用的：正式名称或可核对品牌 + 国家/地区线索 + 至少一条可核对公开痕迹（网站/LinkedIn/注册等），且本对话或已知材料中无未解释的身份矛盾。

**不足** → 执行背调或标明无法有效主体背调。

有**任一**可检索身份且可联网 → 在「不足」时直接查，不问用户：

- 公司名 / 品牌名 / 网站 / 企业邮箱域名 / 买家姓名 / LinkedIn / 电话 / 地址

**无可检索身份**：不卡住。写：

> **当前无法完成有效主体背调：现有信息只能确认客户的需求内容，不能确认其商业主体。**

然后继续项目判断。

无联网：写「需要外部验证」，不得凭记忆断言存在/不存在。

## 按项目阶段的背调策略

| 阶段 | 策略 |
|---|---|
| **New Lead** | 默认 Quick Check |
| **Qualified Inquiry** | 身份不足则补一次；重点已转向项目真实性、需求匹配、投入程度 |
| **Active Project** | 通常不每次重背调公司；检查**新的未知**（突然账期、改收货主体、换公司抬头、高额投入、合规产品升级） |
| **Re-engagement** | 侧重 Recency：是否仍活跃、联系人是否仍在、项目背景有无变化 |

## 原则

1. **只建事实层**：搜索时不贴「靠谱/骗子/诚意高」。
2. **只查会改变下一步的东西**：要不要回、怎么回、是否报价/寄样、投入多少、是否先验证。
3. **「未找到」=「未发现公开证据」**，禁止写「不存在」。
4. **矛盾记为 Risk Facts**，不叫 Red Flags。
5. **持续项目沿用已有背调事实**；仅对缺口或新风险做增量更新，并在输出中注明「沿用 / 增量」。

## 深浅两档（Skill 自判，用户不选）

### Quick Check

默认：公开身份 + 业务 + 活跃度 + 与询盘匹配。够判断是否正常推进。

### Deep Check（任一触发）

- 大额项目 / 要求账期 / 独家代理 / 大量免费开发 / 高额样品投入
- 高风险国家 / 强合规产品 / 主体信息明显矛盾
- Active Project 中突然出现上述新未知

仍服从最小有效动作——不是每个小样品都做企业调查报告。

## 六类核查（只取可能改变行动的）

### 1. Identity｜主体是谁

公司/品牌正式名称、国家/地区、网站、主体公开痕迹、邮箱域名一致性、买家姓名与公司公开关联。

### 2. Business｜实际做什么

主营、品类、B2B/B2C、角色（brand / importer / distributor / retailer / sourcing / manufacturer）、主要市场、与询盘产品关联。

例：官网 golf、询盘 snow → **事实**「未发现 snow category」；**推断**「可能是新品类扩张」——分开写。

### 3. Footprint｜真实经营痕迹

多个相互独立、互相吻合的现实痕迹。不是「有网站=真实」。

### 4. Recency｜现在还活跃吗

分条记录最近可确认活动。旧网站 ≠ 停业；注册仍在 ≠ 近期活跃。Re-engagement 必查。

### 5. Inquiry Fit｜询盘与主体匹配

先写匹配度**事实**，不在此步否定客户。

### 6. Contradictions / Risk Facts｜矛盾与风险事实

邮箱国别与注册不符、域名与公司名无关、自称 manufacturer 但官网像 retailer、成立时间与「20 years」不符、地址查不到、主体状态异常、品类与询盘无关等。先记事实，再进判断。

## 背调输出块

```markdown
## 外部背调事实

**档位**：Quick Check / Deep Check / 沿用已有 / 增量核查（一句说明）
**Buyer Identity Evidence**：充分 / 不足（一句）

### 身份
- Company / Country / Website / Buyer / Email domain

### 业务
- 主营 / 商业角色 / 目标市场 / 与本次询盘的关联

### 公开经营痕迹
- ...

### 最近活动
- ...

### 发现的矛盾 / Risk Facts
- ...

### 未找到
- ...（「未发现公开证据：…」）

### 来源
- Source 1 / Source 2
```

身份不足无法背调 → 短句替代，不编造空表。  
身份已充分且无新风险 → 可写「沿用已有背调事实（日期/来源）」+ 仅列本轮新检查项（若有）。

## 背调事实 → 判断层

完成后才合并 Company Context 与项目材料，进入清晰度循环（见 `clarity-engine.md` / `decision-engine.md`）：

事实汇总 → 推断 → 未知分类 → 关键未知与解决路径 → 主动澄清 / 并行推进 → 最小有效推进 → 承诺边界 → 停止条件

推断须指向背调事实或客户原文；禁止在身份证据不足且可检索未检索时，仅凭语气做主体/阶段断言。
