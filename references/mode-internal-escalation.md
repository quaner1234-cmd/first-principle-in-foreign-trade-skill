# Mode 9 — Internal Escalation / Strategic Account（内部升级与战略客户）

**触发**：项目具有以下任一特征时，考虑升级到管理层或对应现实责任人，而不是自己止损或硬扛。

## 升级信号

- 战略级客户
- 重大品牌
- 可能带来供应链升级（合规体系、质量标准、品牌背书）
- 当前条件超过业务员权限
- 需要特殊定价
- 需要公司承担前期投入（测试费、审计费、样品投入）
- 普通流程正在阻碍重要机会

## 升级前先降噪

升级不是把整份客户邮件、所有搜索结果、全部 Unknown 原样转发给管理层或同事。

先按 **Tool-before-Question + Wide In → Narrow Out** 做最小整理：能公开查的先查，能形成 Candidate Recommendation 的先形成；真正需要对方决定或验证的内容再上交。

默认 Handoff：

1. **推荐 / 请求决定**：一句话；
2. **必要依据**：1–3 个最重要事实；
3. **需要对方确认的问题**：1–3 个，且答案会改变下一步。

只有决策确实依赖不同 trade-off 时，才给少量 options，并明确首选。完整研究和来源按需补充。

## 输出内容

```markdown
### 为什么值得升级
（战略价值：不只是这一单的利润，是可带走的供应链升级能力）

### 当前推荐
（一句话：建议公司做什么 / 批准什么）

### 管理层需要知道哪些事实
（只保留 1–3 个会影响决定的事实）

### 当前常规流程可能损失什么
（如果按常规流程走，会卡在哪个结构性差距上）

### 请求管理层做哪个具体决定
（特殊定价授权？合规投入预算？项目级支持？）
```

## 关键纪律

> **不要默认认为"价格不匹配 = 止损"。**

对战略客户：
- 短期利润不是唯一变量——进入供应体系的长期价值（学习、品牌背书、能力升级）可能超过这一单
- 业务员掌握客户重要性，但信息没传到能决策的高层 = 组织不确定性没消除
- 一页纸的"项目战略简报"可以改变结果，但简报应服务于一个具体决定，不是资料仓库
- 广泛研究是为了降低决策人的判断成本，不是把信息处理工作重新交给对方
